## 用户要的功能

电脑已有配置完成的 v2rayN，本项目不替代其节点客户端，不购买 SDK，不要求新增节点或账户。用户允许选择规则、全局、TUN 的组合，允许既有代理模式影响其他应用。

项目开启保护后，监控用户指定的应用，确保其公网连接走既有代理，禁止使用原网络的公网出口。发现绕过、出口不符合已确认的代理路径，或保护条件失效时，先维持网络阻断，再终止所选目标应用及已确认归属的联网组件，记录原因。用户明确授权异常时终止目标应用；不得扩大到 v2rayN、所有浏览器、共享 node/svchost 或本项目以外的程序。

DNS 和 WebRTC/UDP 防泄露是可选增强：能可靠实现的纳入，未完成的明确标注，不再作为全部核心功能交付的强制前置。该降级不允许声称未验证的 DNS/WebRTC 已安全，也不允许已知直连路径绕过核心公网出口约束。

真实应用测试可使用 Google Chrome、Codex 或其他隔离程序。Claude 桌面端仅在临时 Windows Sandbox 使用全新安装和配置，继续禁止操作宿主 Claude 安装及用户数据。Chrome 使用隔离测试配置。Codex 测试不得结束当前开发会话或读取真实认证资料。

## 当前选用的验证方向

优先验证 **v2rayN TUN + 全局代理路由 + 本项目独立阻断/异常终止**。TUN 用于接管不遵循系统 HTTP 代理的应用；全局用于避免规则分流到 DIRECT。独立阻断必须在 TUN/代理退出或路由改变时仍有效。TUN 路线未通过目标应用与故障实测前，不得因为网卡存在或出口网站返回代理 IP 就开放桌面保护。

这是一项待验证的工程选型，不是对当前 TUN 模式安全性的验收结论。若现有 TUN 与按应用阻断无法相容，回到已验证的受限应用中转路线，不要求用户自行解决底层实现。

## 保护工作流

1. 只读识别既有代理入口和受管应用完整身份。只允许本次选择的应用及已确认组件进入终止范围。
2. 核验代理可用性、当前代理出口及目标路径，先安装并核对阻断，再启动或接管应用。已经运行的应用须处理既有连接，不能把之前的流量追溯记为已保护。
3. 实时连接/策略事件与周期出口观测配合。项目自身通过代理查询 IP 只能说明项目探测路径可用，不能证明目标应用每条连接都走代理；TCP 连接表、进程名称和网卡名称同样不能单独证明公网出口。
4. 发现受管程序绕过代理、TUN/代理失效或监控证据失效，先阻断再终止受管应用。无法读取证据标记“无法确认保护”，不伪报“已发现真实 IP 泄露”。代理出口改变也不能直接断言是原网络公网 IP；按出口不符合预期停止并重新核验。
5. 显示触发时间、受管应用身份、检测依据、阻断和终止结果。终止失败时保留阻断，明确报告失败，不显示“已停止”。
6. 故障后不自动重启目标应用或自动解除限制；恢复前重新检查代理与策略。

IP 轮询只能事后发现异常，已经发出的流量无法撤回。“必须走代理”仍需要前置路径限制。不能将“检测后结束进程”描述为零泄露保证。
