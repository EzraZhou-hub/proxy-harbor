# P0：不同路径辅助程序、DNS 与重启恢复

日期：2026-11-13。系统层实验仅在离线 Windows Sandbox 执行。用户单独授权了临时来宾的一次重启，未重启宿主机；没有启动、探测或操作 Claude，没有读取真实节点凭据或修改宿主机 DNS、代理、防火墙。

## 不同路径的辅助程序

新增固定临时辅助程序 `C:\P0Lab\.local\p0\bin\helpers\proxy-harbor-p0-helper.exe`。它是本项目探针的构建副本，使用不同名称及完整路径，所以拥有与父程序不同的 WFP 应用身份，不是靠同路径继承来通过实验。

`p0-helper-guard.exe` 只接受该固定实验路径，不能传入任意应用。它为辅助程序安装四条持久限制：只能使用指定的 IPv4 回环 TCP 入口，其他 IPv4、UDP、端口及 IPv6 被阻断。辅助程序的 sublayer 为 `78c0ad14-2bd0-47bd-b5ec-0132d73b3e8c`，过滤器为 `c7abcf51` 至 `c7abcf54`，独立于父程序；归属和完整应用身份核对沿用原生工具。

系统测试先为父程序和辅助程序分别安装规则，再启动进程链。辅助程序未注入时不能直连，注入后子孙进程的普通连接、同步及带回调 DNS 能经过选定上游；转发进程退出后，辅助程序仍被阻断。不同路径的对照程序保持正常。清理同时核对两组规则。

这完成了**固定辅助程序清单的预先限制与进程继承机制实验**。尚未自动发现真实应用所有辅助 EXE、验证跨架构/提权进程，也没有把机制接入桌面应用启动。不能将两个临时身份扩写为任意应用兼容性通过。

## DNS 加固

同步 GetAddrInfoEx、DnsQuery W/A/UTF8/Ex 仍通过候选的 FakeIP 映射保留域名，连接时交给上游。新增 DnsQueryEx v1 的回调完成及 DnsCancelQuery：生成受控结果后排队回调，维护请求生命周期；取消与完成竞争时只回调一次，返回已完成或已取消，不回退本地解析器。内存释放仍识别自身分配，避免交给系统释放器误释放。

带回调的 DNS 不再一律拒绝。其 pending、回调、取消规则依据微软 [DnsQueryEx](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsqueryex) 与 [DnsCancelQuery](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnscancelquery) 接口约定；测试要求收到一次完成通知，随后能用原始域名完成代理回显。取消测试接受合法的完成/取消竞争，但要求不建立目标连接。

较新的 DnsQueryRaw 出口若存在则安装拒绝钩子，返回不支持。原始请求尚无受控实现，不能放回系统 DNS 服务执行。其测试核对拒绝入口及无上游目标请求，不代表已做真实 DNS 抓包。GetAddrInfoEx 的 overlapped 异步模式仍明确拒绝；不支持的 DNS 类型/结构版本也没有系统解析回退。

**仍未完成完整系统 DNS 服务覆盖。** 当前证据针对已列出的用户态 API，不包括直接调用共享 DNS 服务 RPC/ALPC、任意未覆盖接口或绕过钩子的程序。没有停止 DNS Client 服务、关闭全局 DNS/IPv6、修改系统解析器或拦截其他应用。冷/热缓存、真实外部 DNS 观测、AAAA/双栈及所有解析接口还不能标为整体验收通过。

## 恢复机制与真实来宾重启

`scripts/p0/guest-recovery.ps1` 是独立于桌面和转发进程的实验恢复工具，仅允许在本项目隔离来宾中运行：

1. Arm 先写入带所有者、版本、入口端口和工具摘要的恢复记录，再安装父程序及辅助程序规则。意图记录早于持久规则变更。
2. 新进程执行 Status 时读取记录、核对摘要并检查真实规则，显示 `blocked_pending_recovery`；不自动解除限制。部分安装显示需要恢复，不伪装成完整保护。
3. Release 是显式操作，检查临时目标程序是否仍在运行，再通过固定范围工具清理自身对象；不重置整个防火墙。记录损坏或工具变化时拒绝修改规则。
4. 重复 Release 可安全执行；恢复记录继续保留，便于核对状态。

重启证据包：`.local/p0/sandbox/20261113-092948-3b49bb/`。临时来宾内注册了一次启动任务，测试后删除；只有来宾执行 Restart-Computer。微软说明 Windows 11 22H2 起沙盒支持内部重启并保留数据，见 [Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/threat-protection/windows-sandbox/windows-sandbox-overview)。

该包 `results/reboot-before.txt` 与 `reboot-after.txt` 记录的来宾启动时间分别为 `2026-11-13T09:29:20.9036530Z` 和 `2026-11-13T09:31:40.1669830Z`。重启后的 26 条具名观测全部通过：8 条规则仍存在，父程序和辅助程序 TCP4/TCP6/UDP4/UDP6 继续被阻断，对照程序正常；损坏记录拒绝清理且规则保留；显式恢复后规则为 0，四类通信恢复，再次恢复仍成功。

该轮其他阶段也通过：19 个协议顶层测试、受控转发的 6 组/168 条观测、透明接管的 6 组/270 条观测。后续加固 DnsQueryRaw 后另跑完整回归，不再次重启来宾；最终包见 [当前进度](p0-transparent-progress.md)。

这证明了本实验范围的持久规则跨来宾重启及独立恢复，不是硬断电、宿主机重启或真实应用自启动顺序的完整验收。启动后默认保留阻断，尚不会自动恢复真实代理会话；后台服务的正式部署仍属于后续阶段。
