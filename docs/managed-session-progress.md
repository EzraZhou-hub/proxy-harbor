# v2rayN 会话守护原型与 P0 验证

收尾日期：2026-11-15。实际系统验证执行于 2026-11-14。根据用户最新替换的约束，**P0 总体仍为 `not_accepted`，桌面启动入口已在前后端边界禁用，不进入 P1**。以下结果是受控原型的验证证据，不是任意应用的完整防泄露承诺。

## 已实现的原型

- 原生 `native/session/guardian.c`：每次会话独立 GUID、持久 WFP 限制、明确所有者与逐条件核对。已登记安装组件的出站仅允许 TCP `127.0.0.1:<本轮代理端口>`，阻断其他 IPv4 目的地址/端口/协议及全部 IPv6；入站限制为回环 IPv4，IPv6 拒绝。
- 启动前核验代理监听及进程身份、sing-box TUN 默认路由、获准 HTTP 入口的 HTTPS IPv4 出口。完整 TLS 校验、禁止跳转；固定观测服务为 `https://api.ipify.org/`。不获取原网络的公网 IP 作为对照，不读取节点配置或凭据。
- 先装规则，再以挂起状态创建目标进程并纳入 Windows Job，最后恢复执行。目标使用父界面的用户令牌及独立数据目录；不会接管已运行的同安装程序。已发现同安装组件在运行时拒绝启动，不强行关闭旧窗口。
- 约 200 毫秒轮询代理/TUN 存活、路由、Job 组件及本项目丢包事件，约每秒核对策略。另一个线程每 10 秒经获准代理复核出口，不让外部请求等待阻塞终止循环。以上是调度间隔，不是最坏故障反应时间保证。
- 出现绕过事件、未知组件、代理或 TUN 失效、出口异常、父界面退出时，先尝试追加全阻断规则，再终止本次 Job 并核对进程退出，然后清理本会话规则。终止不能确认时保留限制；守护程序崩溃时 Job 关闭终止进程，持久规则保留，需独立恢复。
- 仅允许按原会话记录和逐项匹配的过滤器进行恢复；错误端口拒绝恢复且事务回滚，其他身份的对照程序不受目标规则影响。保存/恢复诊断事件采集状态，恢复记录先于修改写入。
- `internal/session`、桌面绑定、Chrome 配置项和 Vue 会话面板已经接线；旧两应用配置可补入 Chrome。浏览器测试服务禁用真实启动。按 2026-11-15 替换约束，原生桌面也由 `sessions_native.go` 明确拒绝准入，存在守护二进制不代表可以开启保护。
- 当前代码继续锁定 Claude。Codex 的独立目录/代理参数只属于待验证的适配代码，不能据 Chrome 测试宣称 Codex 登录、对话或全组件兼容。

## 选用的网络路径

实际受管程序路径是 **受限程序 → 明确的 HTTP 代理入口 → 现有 v2rayN 全局出站**。TUN 开启及其存活/路由仍作为本轮监督条件，但没有让受管程序自由连接公网再假定 TUN 会接管。

先前在来宾独立进行的透明 TUN 出口查询超时，见保留包 `20261114-111142-bbb9a2`、`20261114-111848-8caf52`。第二包明确记录经 HTTP 入口查询成功、透明 TUN 查询返回 WinHTTP 12002。最终把必需出口核验绑定到受管程序唯一获准的显式代理路径；不关闭证书验证，也没有放开任何直连规则。透明 TUN 接管本身不记为已通过。

宿主只读核验曾确认 `singbox_tun` 活跃、默认 IPv4 路由指向它、监听入口为 `127.0.0.1:10808`，代理及当时 TUN 观测出口为 `131.103.130.202`。这是当时的观测，不是永久固定出口或全部目的地址路径的证明。

八类场景为正常结束、TCP4、TCP6、UDP4、UDP6 绕过、代理入口消失、未知子程序和守护程序崩溃。检查代理连接/既有隧道、已登记子进程、本次根/子进程终止、精确终止原因、错误恢复端口拒绝、规则持久保留及独立恢复、同名不同路径对照与最终规则为零。通用场景运行在固定来宾 `fixture` 模式，跳过真实 TUN 与公网出口核验，不能把这 98 条写成真实应用公网测试。

真实 Chrome 使用电脑已有 Chrome 157.0.8103.51 的**程序文件副本**，全新配置目录；sing-box 1.14.3 与 Wintun 文件只作来宾实验基础设施，不加入本产品最终依赖。未复制浏览器账号/用户配置。来宾临时 TUN 经限时文件通道连接宿主已配置的 HTTP 入口，不读取任何节点资料。

Chrome 安装副本枚举到 10 个 EXE，启动前安装 60 条限制。正常结束、守护程序崩溃、TUN 退出三个场景都从浏览器实际访问 HTTPS IP 回显页面，分别得到 `131.103.130.202`，与同轮代理核验一致。浏览器使用默认证书验证，无忽略证书选项。随后分别核对关闭/终止、持久规则保留和恢复、最终过滤器清理。测试是无账号 headless 工作流，不代表日常 GUI、登录、插件或外部运行时已经完全兼容。

Windows 控制台宿主只对系统目录的精确 `conhost.exe` 路径作为必要组件处理，不按同名进程普遍放行；它未被宣称为受代理的通用共享服务。

普通 Go 测试、4 项前端草稿回归、5 项真实 Go 后台＋Edge UI 回归、Windows 桌面构建均通过。2026-11-15 又验证了前后端桌面准入关闭：直接调用启动方法在查找配置、启动进程及策略修改之前即拒绝。最终构建日志为 `.local/p0/managed-final-build.log`。

## 为什么仍然不能开启桌面保护

关键缺口是**未知可执行子程序缺少继承的网络限制身份**。当前原型在进程创建之后才检查 Job 成员的 EXE 路径。未登记的子程序可能在下一次检查并被结束前尝试连接；固定 Chrome 安装副本测试不能证明所有应用组件都不存在这个窗口。不能把“随后已杀掉进程”写成“之前没有机会泄露”。下一项 P0 应先补这一边界，再进行对应故障验证。

还未证明完整 Codex 工作流、任意共享服务、外部运行时或所有既有连接类型。DNS/完整 WebRTC 继续标记未验证，不能因阻断 UDP 就声称 WebRTC 的所有地址暴露形式均已解决。最早开机与跨重启持续保护按最新简化会话范围保留未覆盖，未自动重启任何机器。

## 收尾及宿主边界

2026-11-15 已停止项目临时来宾及中转，限时通道没有续期。宿主没有安装本轮会话规则、切换代理/TUN 或终止真实 Chrome/Codex；没有 Claude 测试。宿主原六组固定项目规则只读核查为零。

新增会话命名空间的全量只读枚举返回 Windows 5（访问拒绝），因此该项独立核对**未验证**，不得把错误返回中的零计数作为成功。未为此申请 Windows 管理员提升或修改规则；原始结果见 `.local/p0/managed-host-inventory.json`。本轮所有规则安装/删除与故障终止实验只在来宾完成。
