# 系统 DNS 临时限制与恢复

2026-11-17。本轮按用户授权允许保护期间影响全机 DNS；结束后须恢复。Windows Sandbox 仅用于系统实验，最终运行不以虚拟机为依赖。Claude 未启动、读取或测试，宿主未安装网络规则或修改 DNS。

## 实现

`native/session/system_dns.c` 创建六条持久 WFP 规则：IPv4／IPv6 的目标端口 53／853 各两条，以及针对 svchost.exe 和 Dnscache 服务 SID 的全端口出站限制两条。后者不依赖解析器端口，也不依靠此前失败的按用户 RPC 过滤。规则在应用启动前安装并周期核对。Chrome 自身继续使用代理解析和禁用独立 DoH 的临时用户策略。

没有改写网卡 DNS、DNS 服务启动类型或用户原有 DNS 策略；恢复是精确删除本会话拥有的六条规则。普通程序的传统 DNS 和系统 DNS 服务解析在保护期间也可能不可用。其他程序自行通过 HTTPS 发起的 DoH 不属于这六条规则的全机覆盖承诺。

正式请求为 PH4，保留 TUN 要求；PH5 仅在固定来宾环境允许，用于独立验证 DNS 生命周期。旧 PH1／PH2／PH3 解析与恢复兼容保留。桌面准入仍关闭。

## 故障与恢复顺序

DNS 规则使用持久模式，不随守护程序崩溃直接消失。独立恢复监督进程持有受管账户 SID 和守护程序的 PID／创建时间绑定。正常停止、桌面退出或守护程序崩溃时，先终止并确认该身份下的进程全部退出，再删除系统 DNS 规则。恢复监督进程先崩溃时，守护程序检测后结束应用并接管恢复。

两进程同时终止时，保留限制，下一次通过原会话执行显式恢复。不能承诺任意双重故障或系统崩溃后无需恢复操作。会话记录损坏、进程退出无法确认或规则归属不符时拒绝冒险放行；因此异常情况下全机解析可能持续受限，界面应显示需要恢复。恢复不删除外来或被修改的规则。
