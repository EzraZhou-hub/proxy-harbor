状态：已按用户后续要求先交付桌面基础框架，详见 [框架交付记录](scaffold-status.md)。P0 原生内核验证尚未完成；未安装驱动、服务或修改本机网络。本文取代初期调研中的“浏览器版优先”实施建议；早期调研保留作参考。

## 1. 产品目标与验收边界

用户使用已有国外 IPv4 出口代理，在 Windows 桌面上正常运行已安装的 Claude、Codex。相关公网连接只能经过指定代理；无法代理时阻断，不回退直连。其他应用保持原有联网方式。

核心是网络路径保护：IPv4 代理 + 防绕过限制 + DNS 保护。不是终端工具，不做设备信息或地区身份伪装，不承诺服务端地区判断、账号状态或服务本身可用性。

严格首版策略：

| 类别 | 规则 |
| --- | --- |
| IPv4 TCP | 经过受控代理转发，禁止目标应用直接访问公网 |
| 公网 IPv6 | 阻断目标应用的公网 IPv6；不关闭系统或物理网卡 IPv6 |
| DNS | 目标域名经过代理远端解析或受控的代理内 DNS 路径；失败不回退本地解析 |
| 公网 UDP / QUIC | 首版统一阻断；UDP 探测能力保留，但不等于应用已获准转发 UDP |
| 代理异常 | 保持目标应用阻断，不因界面或转发进程退出而放开直连 |
| 本机通信 | 仅保留已验证的代理入口、登录回调及必要辅助通信，明确列出例外；不笼统放行所有本地转发服务 |
| 其他应用 | 不被本项目代理或阻断；不修改全机默认网络策略 |

不能仅依据 IP 查询网站显示代理 IP，便认定保护成功。普通功能测试与 DNS、IPv6、UDP、故障时防直连测试必须分别通过。

首版保护范围按应用安装实例及经验证的联网组件定义，不承诺把同一路径 EXE 的两个窗口当成两个独立网络身份。共享运行时、打包应用、沙盒或虚拟机内组件必须逐项验证；不能确认覆盖时标记“不支持/未验证”，不能显示整应用“已保护”。

## 2. 已确定的技术栈

| 层 | 选择 | 职责 |
| --- | --- | --- |
| 首发平台 | Windows 11 x64 | 原生桌面版优先；其他 Windows 版本、ARM64 和其他系统后续单独验证 |
| 桌面壳 | Wails 3，初始基线 v3.1.0 | 窗口、托盘、退出流程、目录选择、前后端桥接 |
| 界面 | Vue 3 + TypeScript + Vite | 应用列表、代理配置、保护状态、检测与日志；需要时使用 Pinia 管理状态 |
| 核心与后台服务 | Go | 会话编排、应用适配、诊断、规则生命周期、恢复；Go 工具链满足所锁定 Wails 的要求 |
| Windows 网络转发 | 优先评估 ProxyBridge 原生 C 核心 + WinDivert | 通过受限本机接口接入；不假设内核已经具备完整防泄露能力 |
| 独立阻断 | Windows WFP 用户态管理 API，具体策略须经 P0 证明 | 与转发进程解耦，覆盖 IPv4、IPv6 及故障状态；不从零编写内核驱动 |
| 服务通信 | Windows Named Pipe | GUI 普通权限，后台承担必要权限；校验调用身份、限制命令和管道 ACL，不开放通用高权限命令执行 |
| 配置 | 带版本号的 JSON，原子替换 | 应用与代理配置；不写入密码 |
| 状态与历史 | SQLite | 会话、规则归属、恢复日志、检测历史；P0 后锁定兼容 Go 驱动与迁移方式 |
| 凭据 | Windows Credential Manager 或用户绑定 DPAPI | GUI 安全读取并经受限 IPC 交付服务；验证跨用户/服务身份边界；不落入日志、命令行或普通配置 |
| 打包 | NSIS x64 安装包 | 安装、更新和卸载服务、依赖及本项目组件；跟踪第三方组件版本与许可 |

Go、前端依赖、原生核心及驱动在进入实现时锁定精确版本、来源和摘要，提交锁文件及依赖清单。Wails v3.1.0 是本次核对的非预发布基线，不在开发过程中自动追随最新版本。

编译 Windows 原生 C 部分需要相应 Windows SDK 和 C/C++ 构建工具；安装操作系统组件与日常 GUI 权限分开。安装的驱动不因关闭界面而卸载，日常退出清理的是本项目会话与规则。

## 3. 代理支持范围：HTTP、HTTPS、SOCKS5 都支持

这是用户已确认的首版要求，不因某个候选内核缺少实现而静默删减。

| 类型 | 首版要求 |
| --- | --- |
| HTTP 代理 | HTTP CONNECT 转发 HTTPS 等 TCP 连接；支持无认证及用户名/密码认证 |
| HTTPS 代理 | 与代理入口本身建立 TLS，再执行 CONNECT；正常验证证书和服务器名，不通过关闭验证解决问题 |
| SOCKS5 | TCP CONNECT、远端域名、IPv4 目标及用户名/密码认证 |
| 本地代理软件 | 接入其 HTTP/HTTPS/SOCKS5 监听端口，按真实协议处理；检测循环代理风险 |

“HTTPS 目标经 HTTP CONNECT”与“代理入口本身为 https://”是不同能力，测试和界面均分开记录。若原生内核不支持 HTTPS 上游，可以评估受控本地适配层；同样必须通过 DNS 和故障阻断验收。

首版默认单一指定代理，无自动切换其他出口或直连。代理 IPv4 入口与最终 IPv4 出口是两个概念；回显服务观测到的出口需要单独展示。动态住宅代理可能按连接分配出口，不能凭一次回显承诺所有连接使用同一固定地址或国家。

严格模式需设计代理入口域名的引导解析：优先支持明确 IPv4 入口或预配置入口 IPv4 映射（HTTPS 保留正确 SNI/证书验证）。目标应用 DNS 与代理入口解析分开记录，保护期间不能暗中用系统 DNS 补救失败。

## 4. 开源项目的采用方式

| 项目 | 决策 | 必须解决的问题 |
| --- | --- | --- |
| ProxyBridge | 第一候选：验证后复用/维护分支，包装为可替换 EngineAdapter | HTTP 代理下 UDP 直连、缺少代理配置时直连、DNS 域名获知及远端解析边界、引擎故障行为 |
| ProxiFyre | 对照候选，P0 第一候选不合格时评估 | IPv6 分片直通、非管理员模式归属不明流量直通；第三方依赖与 AGPL 许可单列 |
| proxybox | 参考持续阻断、服务/UI 分离、故障状态展示 | 已披露整机网络影响、进程覆盖和实机验证不足，不直接作为首版底座 |
| MyIP / dnsleaktest | 参考多来源探测、DNS 唯一域名会话式观测 | 第三方服务故障与证据边界；DNS 地区不同不能直接判泄露 |

ProxyBridge 仓库为 MIT；WinDivert 等第三方组件许可另行记录。参考架构不等于复制源代码；如采用 GPL/AGPL 项目代码，实施前单独确定派生版本及分发安排。当前不决定本项目最终许可证。

## 5. 模块与进程边界

```text
普通权限桌面界面（Wails + Vue）
  └─ 受限 Named Pipe
       └─ 管理服务（Go）
            ├─ ProfileStore / SecretBroker：配置与凭据
            ├─ ApplicationAdapter：桌面应用发现、身份、组件清单
            ├─ SessionController：启动、保护状态、结束流程
            ├─ EngineAdapter：原生转发核心与 HTTP(S)/SOCKS5 适配
            ├─ PolicyManager：持续阻断、策略核验与归属记录
            ├─ DNSController：目标域名解析路径与验证
            ├─ Diagnostics：出口、DNS、UDP、IPv6、连通性证据
            └─ RecoveryJournal：恢复、更新、卸载核对
```

界面不直接修改系统规则。服务不信任前端传来的“已保护”状态；状态由规则核验和探测证据导出。内核适配器必须能报告不支持的能力，不以“调用成功”代替策略生效。

应用适配按 Claude 桌面版、Codex 桌面版分别交付，记录测试版本、安装来源、联网辅助进程和实际工作流。优先识别完整路径、包身份、用户及必要的进程关系；不全局匹配 node.exe、svchost.exe 等共享名称，不自动接管所有子进程。

首次保护前处理既有连接：要求目标应用完整退出并由启动器重新启动，不能假定给已经建立的连接加规则就能改变其路由。更新后路径或组件变化，要重新验证适配而非沿用旧的绿色状态。

## 6. 最难的两个技术前置条件

### 6.1 DNS 接管

需要在目标解析请求发往本地 DNS 之前，可靠地保留/接管域名，并通过代理解析。候选包括内核已有的应用解析接管能力，或经过验证、作用域足够小的应用原生配置适配；仅在 TCP CONNECT 时把已经解析过的域名交给代理，不足以证明未发生本地 DNS 查询。

验证系统解析器、原始 UDP/TCP DNS、自带 DoH/DoT、辅助进程及缓存冷热两种情况。系统 DNS 服务可能代发请求，不能以“只封目标 EXE 的 53 端口”作为完整方案，也不能全局封锁 svchost.exe 来补漏洞。

没有可靠接管方案时，P0 不通过，不能把整个应用标成受保护。不能靠修改全机 DNS 或忽略无法归属的请求来通过验收。

### 6.2 转发与阻断相容，故障时持续生效

系统规则必须允许受控转发所需的连接，同时禁止目标进程公网直连；实际放行条件要结合转发引擎的重定向层序验证。不能简单叠加一个“全部阻断”规则就假设代理仍可工作。

界面、服务、转发核心分别退出时，都需证明目标流量无法转为直连。不能仅依靠崩溃后轮询补规则；阻断需要在正常保护期间就独立生效。验证持久规则、启动顺序、既有连接与 WFP 重新授权，不能只证明新连接被拦。

无法同时实现持续阻断和其他应用正常时，该候选方案淘汰。若 P0 两项均无候选通过，交付失败原因及可选架构，暂停承诺完整防泄露，不继续用界面掩盖能力缺口。

## 7. 生命周期与退出行为

```text
未开启 → 检查应用/代理 → 安装并核验限制 → 转发及 DNS 验证
       → 就绪待启动 → 启动应用 → 保护中
任意保护阶段故障 → 已阻断 / 保护异常（不允许回退直连）
保护中 → 请求结束 → 处理仍在运行的应用 → 清理本项目规则 → 验证 → 未开启
```

“就绪”代表本次预检通过；“保护中”只适用于已验证的应用版本和范围。网络变更或代理故障使状态降级为阻断/异常，不保留过期的绿色状态。

- 关闭窗口默认进入托盘并保留保护，明确显示后台仍在工作。
- “退出并结束保护”是独立操作。目标应用未结束时提示先保存工作并退出，不强制杀掉进程后声称正常完成。
- 目标进程还在运行时，不先删除阻断规则；可取消退出，继续保护/阻断。
- 规则改变前写入可恢复记录，规则 ID 带本项目所有者标识；只清理本项目对象，不重置整个防火墙。
- UI 崩溃时后台继续处理；服务/转发核心异常时目标保持阻断，提供独立恢复工具。
- 重启后先识别残留会话与策略，再处理恢复；不能出现目标应用自启动先联网、保护稍后才建立的窗口。
- 故障后若为了保密保留了目标应用的阻断，必须明确展示；“其他应用正常”不等于“所有目标应用立即恢复联网”。
- 更新/卸载先安全结束受管会话，核对策略清理结果；失败需明确报告，不能把失败记录当成功删除。

## 8. 诊断功能

保留最初提出的本机环境与网络检测需求，但与保护执行分离。

| 模块 | 首版内容 |
| --- | --- |
| 本机环境 | 活动网卡、本地 IPv4/IPv6、DNS、路由、系统代理只读采集 |
| 代理检查 | 入口 TCP/TLS、认证、CONNECT/SOCKS 握手、目标连通性、耗时 |
| 出口观测 | 多来源 IPv4、服务及时间、预期与实测；不据此推导 DNS 已安全 |
| DNS | 唯一子域名外部观测，配合本机连接/抓包证据，区别未观测与通过 |
| IPv6 | 目标应用公网 IPv6 尝试是否被阻止；双栈及 IPv4 映射地址场景 |
| UDP | 目标应用 UDP 阻断；探测协议与端点单独记录 |
| 连通性 | 目标应用登录、流式对话、必要工具调用；解析/TCP/TLS/HTTP 分层错误 |
| 报告 | 脱敏 JSON/HTML，记录版本、测试上下文、原始错误、未覆盖项 |

默认诊断也使用受保护路径，不能为了获取“本地真实 IP”暗中直连。需要本机直连对照时独立展示检测作用域，不代表受保护应用被放行。第三方检测服务不可用时显示无法验证，不显示安全。

## 9. 分阶段开发与交付

各阶段以验收结果过关，不先给出未经验证的工期承诺。阶段 0 未通过前不投入完整界面开发。

| 阶段 | 工作与交付 | 通过条件 |
| --- | --- | --- |
| P0：内核验证 | 固定候选源码版本；最小控制工具、受控测试进程、抓包/连接/DNS 观测记录、选型结论 | HTTP/HTTPS/SOCKS5 均可工作；DNS 接管、IPv4/IPv6 阻断、UDP 阻断、故障持续阻断、其他应用正常均有证据 |
| P1：后台核心 | Go 服务、EngineAdapter、PolicyManager、受限 IPC、状态机、恢复工具、存储 | 启停幂等、异常可恢复、不清理无关规则；凭据不出现在日志与命令行 |
| P2：桌面应用适配 | Claude、Codex 各自的发现、启动、组件清单与兼容报告 | 两个已安装桌面应用分别通过登录、流式会话及约定工作流；不支持组件明确列出，不扩大保护声明 |
| P3：可用桌面版 | Wails/Vue 四个主要页面：概览、应用、代理、诊断/日志；托盘与安全退出 | 用户无需终端操作即可配置、验证、启动、观察、结束；UI 状态与服务一致 |
| P4：发布候选 | 安装/卸载包、依赖和许可清单、升级恢复、使用说明、版本化验收报告 | 干净 Windows 测试环境及目标真实电脑均通过；安装、更新、卸载、故障恢复有实测记录 |

P0 的预验证优先在可恢复的 Windows 测试环境进行；虚拟机无法代表实际电脑的全部行为，P4 仍需真实目标机器验证。任何系统级测试都要在实际执行前列出具体组件及影响范围；本计划不执行安装或规则修改。

## 10. 必须覆盖的验收矩阵

| 测试 | 预期 |
| --- | --- |
| HTTP / HTTPS / SOCKS5，分别无认证及账号密码 | 指定代理路径工作，错误密码保持阻断 |
| 支持 IPv6 的真实网络、显式 IPv6 地址、AAAA 优先、双栈套接字 | 目标应用无公网 IPv6 直连；其他程序 IPv6 正常 |
| UDP 53/443/STUN、多端口与分片探测 | 严格模式不出现目标应用公网 UDP 直连 |
| 冷缓存、热缓存、系统 DNS、DoH/DoT、辅助进程解析 | 无目标域名从非受控本地路径外发；无观测结果标记无法验证 |
| 代理入口不可达、认证失败、远端拒绝、网络切换、睡眠唤醒 | 目标应用保持阻断，不切换出口 |
| 杀转发核心、杀服务、关闭/杀界面 | 目标应用没有新增或残存直连；与正常退出行为分开验收 |
| 保护启用前已有连接、应用自动启动、软件更新路径变化 | 不沿用旧直连；验证前不显示受保护 |
| 同名不同路径进程、共享运行时、外部浏览器登录、插件/VM | 不误拦其他应用；无法覆盖的工作流不计入兼容范围 |
| 浏览器、聊天软件、局域网服务、系统更新 | 不被本项目错误代理或阻断，原始配置保持不变 |
| 正常退出、重启、更新、卸载 | 仅清理本项目对象，状态可核对；失败有恢复路径 |

证据至少包含：操作系统/应用/内核版本、规则清单、接口抓包或等效连接证据、受控目标端观测、DNS 观测、触发故障步骤、预期与实测。代理日志不是唯一证明；“没有日志”也不能直接判定未泄露。

## 11. 首版暂不包含

macOS/Linux、内置终端、设备指纹或地区身份伪装、全机 TUN 模式、自动更换国家或节点、系统 DNS/IPv6 全局开关、自研内核驱动、HTTPS 解密、订阅节点管理。正常 TLS 验证保留，不安装用于解密目标应用流量的根证书。

UDP 代理转发、更多桌面应用和虚拟环境工作流，在严格首版稳定后逐项加入，不能降低默认阻断标准。

## 12. 尚待实际验证的事项

- Claude、Codex 在用户电脑上的准确版本、安装类型、辅助进程、插件/虚拟环境使用范围。
- 各代理入口对 CONNECT、TLS、SOCKS5 远端域名、认证及出口行为的支持。
- ProxyBridge 与独立阻断策略是否相容，能否可靠接管目标 DNS。
- 现有 VPN、安全软件、防火墙与网络捕获组件的相容性。

这些是 P0/P2 的工作内容，不是要求用户现在提供密码或自行操作终端。P0 前只需普通配置样例描述，实际联网验收阶段再接入真实代理。
