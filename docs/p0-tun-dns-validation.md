## 测试路径与边界

宿主只读核对确认 v2rayN 的 xray 监听 `127.0.0.1:10808`、公网 HTTPS 观测出口 `131.103.130.202`，最佳路由选择 `singbox_tun`（索引 23）。前后代理进程保持相同 PID。

来宾使用从既有安装复制的免费开源 sing-box 1.14.4 与 Wintun，创建真实 TUN。受管 Chrome 通过临时故障注入转发器及有 15 分钟上限的文件通道访问宿主实际代理；宿主不开放新网络监听。PH4 同时启用 TUN 检查、临时账户身份限制和六条持久系统 DNS 规则。故障只在来宾注入。

Chrome 正常路径采用完整 TLS 校验的真实页面输出核对出口；后台核验也执行正式 WinHTTP 代码。短时断连后要求核验记录更新且出口匹配；持续断连、入口进程更换及 TUN 路由失效要求结束应用。恢复后删除本会话规则、身份并重测系统解析。

**这条路径不会让宿主代理核心本身处于来宾的 DNS 限制之下。** 因此不能用它代替本机 v2rayN 在全机 DNS 受限时的引导解析、真实节点重连或内部回退验收。来宾入口重启也不等于实际切换宿主节点。

TUN 配置显式关闭来宾内核自动 DNS 接管，以独立观察项目的 DNS 规则。依据[sing-box TUN 文档](https://sing-box.sagernet.org/configuration/inbound/tun/)，自动路由默认可接管 DNS，Windows 严格路由还可能限制其他接口的 DNS；因此 DNS 恢复对照在停止来宾 TUN 后执行，不把 TUN 自己的阻断冒充项目规则效果。
