# P0：同路径子孙进程与异步 DNS 拒绝

后续更新：不同路径辅助程序、DnsQueryEx 回调/取消和来宾重启恢复已继续实现验证，见 [后续机制记录](p0-helper-dns-recovery.md)。以下保留本轮历史结果及当时边界。

日期：2026-11-13。本轮仅推进 P0；全部系统层实验在离线 Windows Sandbox 中执行，未启动、探测或操作 Claude，未安装商业 SDK 或第三方驱动。

## 修改

`cmd/p0-probe` 增加来宾专用 `-spawn-depth`，只允许 0、1、2 层。必须同时满足隔离来宾标记、`C:\P0Lab` 工作目录及原有固定目标白名单；启动对象必须恰为 `C:\P0Lab\.local\p0\bin\proxy-harbor-p0-probe.exe`。它不接受其他应用路径，不用于启动安装程序或用户软件。

子进程通过普通 Go `os/exec` 创建，由现有候选的进程创建拦截继承钩子。最末级执行原有网络/DNS 探针，各层返回实际 PID 链；验证链长度、PID 为正且不重复。父进程不能仅凭“成功创建子进程”把连接计作通过。

透明系统测试新增四个场景：子进程 Winsock、孙进程 Winsock、孙进程同步 DnsQueryEx、孙进程异步 DnsQueryEx 拒绝。前两个和同步 DNS 场景都必须完成回显，并在模拟上游观测到原始目标域名。异步调用必须返回既定“不支持”，同时模拟上游在检查窗口内未收到请求。

原有两个异步场景也增加未请求上游检查，并把报告键名由 `*_through_proxy` 改为 `*_rejected`。拒绝符合严格模式预期，仍不表示异步 DNS 功能可用；离线实验也不代表已证明全部系统 DNS 无泄漏。

## 未覆盖

本轮各层执行的是同一完整路径的探针，所以已安装的 WFP 应用身份限制自然适用于它们。**尚未解决或验证不同 EXE 路径的辅助程序身份登记、启动前规则布置、跨架构子进程、提权/服务启动或共享系统 DNS 服务。** 不把本轮结果称为真实应用辅助进程全面覆盖。

异步 DNS 仍拒绝，不满足需要该功能的软件的正常工作流。真实应用兼容性、公网 IPv6/UDP、双栈、完整故障与重启恢复等继续待验收，P0 整体仍为 `not_accepted`，桌面保护不启用。
